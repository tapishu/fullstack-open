Dockerfile
コンテナ内のファイルをコピーして変更する代わりに、「Hello, World!」アプリケーションを含む新しいイメージを作成できます。このためのツールはDockerfileです。Dockerfileは、イメージを作成するためのすべての手順を含むシンプルなテキストファイルです。「Hello, World!」アプリケーション用のDockerfileの例を作成してみましょう。

以下のファイル構造の作成
├── index.js
└── Dockerfile

Dockerfile中身
--------------------------
FROM node:24

WORKDIR /usr/src/app

COPY ./index.js ./index.js

CMD ["node", "index.js"]

--------------------------

上記をもとにしたコマンド
docker build -t fs-hello-world . 

ローカルにある画像の一覧は で表示しdocker image ls
削除は docker image rm

以下のplaygroundをpackage.jsonのnameに変更する
DEBUG=playground:* npm start

Dockerfileに以下を足す
---------------------
ENV DEBUG=playground:*
---------------------

これで、Dockerfileからイメージをビルドして実行できます。

docker build -t express-server . //-tで名前をexpress-serverにしている。 .でカレントディレクトリのDockerfileを使うよう指定
docker run -p 3123:3000 express-server //コンテナの起動
左側の 3123: あなたのMac（ホスト側）のポート番号です。
右側の 3000: コンテナの中で動いているアプリ（Express）のポート番号です。

Dockerfile は以下のように変更されます。
-----------
FROM node:22

ビルドステップ中に新しいものをインストールしないため、またバージョンが突然変更されることを望まないため、今回はci を使用します。
-----------------
WORKDIR /usr/src/app

COPY . .

RUN npm ci //clean install

ENV DEBUG=express:*

CMD ["npm", "start"]
-----------------

残る重要な問題は、アプリケーションが権限の低いユーザーではなく、root権限で実行されていることです。
Dockerfileに最後の変更を加え、USER命令を使用してユーザーをroot以外のユーザーに設定しましょう。
-----------------
COPY --chown=node:node . . //コンテナの配下にコピーしたあと、それらの所有者ユーザーとグループをnodeに変更
-----------------

Redisはデフォルトで保存した内容が消えるデータベース。キャッシュに向いていて高速

以下コマンドでコンテナで起動したmongo/redisに接続しながらローカルでのアプリの起動
REDIS_URL=redis://localhost:6379 MONGO_URL=mongodb://root:example@localhost:3456/the_database?authSource=admin npm run dev

redisのデータベースを永続的に保存する方法は以下のコマンドを足す。マウント元のredis_dataは.gitignoreにしまわないとデータが流出
------
services:
  mongo:
    image: mongo
    ports:
      - 3456:27017
    environment:
      MONGO_INITDB_ROOT_USERNAME: root
      MONGO_INITDB_ROOT_PASSWORD: example
      MONGO_INITDB_DATABASE: the_database
    volumes:
    - ./mongo/mongo-init.js:/docker-entrypoint-initdb.d/mongo-init.js
    - mongo_data:/data/db

  redis:
    image: redis:alpine
    ports:
      - 6379:6379
    command: ['redis-server', '--appendonly', 'yes'] # Overwrite the CMD
    volumes:
      - redis_data:/data

volumes:
  mongo_data:
  redis_data:
------

# The first FROM is now a stage called build-stage
FROM node:24 AS build-stage //build-stage というあだ名（名前）を付けるための機能
以下で FROM nginx:1.29-alpine という別のベースイメージに切り替えています。
ここでステージに名前をつけておかないと、「さっきのビルド工程のどこからファイルを持ってきたらいいか」をDockerが識別できなく

RUN npm ci

RUN npm run build

# This is a new stage, everything before this is gone, except for the files that we want to COPY
FROM nginx:1.29-alpine

# さっき名前を付けた build-stage という工程のコンテナの中からこの場所にある dist フォルダ（Reactのビルド成果物）を

nginx.dev.conf
------
# events is required, but defaults are ok
events { }

# A http server, listening at port 80
http {
  server {
    listen 80;

    # Requests starting with root (/) are handled
    location / {
      # The following 3 lines are required for the hot reload to work
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection 'upgrade';
      
      # Requests are directed to http://localhost:5173
      proxy_pass http://app:5173;
    }
# Requests starting with /api/ are handled
    location /api/ {
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection 'upgrade';

      proxy_pass http://server:3000/; #/があると/api/が削られる。ないと/api/もついてくる
    }

  }
}

nfinx.conf
-------
# events is required, but defaults are ok
events { }

# A http server, listening at port 80
http {
  include /etc/nginx/mime.types; # ★ ここを追加（これが無いとJSやCSSの形式をNginxが理解できません）

  server {
    listen 80;

    # Requests starting with root (/) are handled
    location / {
      root /usr/share/nginx/html;
      try_files $uri $uri/ /index.html;
    }
# Requests starting with /api/ are handled
    location /api/ {
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection 'upgrade';

      proxy_pass http://server:3000/; #/があると/api/が削られる。ないと/api/もついてくる
    }

  }
}
