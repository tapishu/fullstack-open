1.React（リアクト）とは？
場所: フロントエンド（ブラウザ側）
正体: ユーザーインターフェース（UI）を作るためのJavaScriptのライブラリ（Meta（旧Facebook）製）。
何をしているの？:
「ボタンを押したら画面の数字が増える」「ログイン状態によってメニューを変える」といった、画面のパーツ（コンポーネント）ごとの変化を効率よく管理・表示してくれます。HTMLとJavaScriptを混ぜたような書き方（JSX）をするのが特徴です。

2.Node.js（ノードジェイエス）とは？
場所: バックエンド（サーバー側）
正体: パソコンやサーバーの上でJavaScriptを動かすための実行環境。
何をしているの？:
もともとJavaScriptは「ブラウザ（フロントエンド）専用」の言語でしたが、「サーバー側もJavaScriptで書けたら便利じゃね？」ということで作られたのがNode.jsです。これを使って、Expressなどのフレームワークと組み合わせ、「API（サーバーの窓口）」を作ります。

3.JavaScript
React、Node.js、npm すべての「土台（共通の言語）」になっているプログラミング言語
フロントエンドもバックエンドもnpmなどで操作する

4.Express
Node.jsでバックエンド（サーバー）を作るときに一番よく使われる超定番のフレームワーク
------
const express = require('express');
const app = express();

// 「/api/hello」にアクセスされたら、JSONを返す
app.get('/api/hello', (req, res) => {
  res.json({ message: 'こんにちは、サーバーです！' });
});

// 3000番ポートでサーバーを起動
app.listen(3000, () => {
  console.log('サーバーが起動したよ！');
});
------

5.Mongoose
Mongoose（マングース）は、Node.jsからNoSQLデータベースの「MongoDB」を直感的かつ安全に操作するための超定番の「ODM（Object Data Modeling）」ライブラリ
MongoDBは「NoSQL」なので、基本的にはどんな形のデータ（JSONのようなドキュメント）でも自由気ままに保存できちゃうのが特徴です。
しかし、自由すぎるがゆえに「うっかり違う形のデータを入れちゃって、後からアプリがバグった…」ということが起こりやすくなります。

6.Axios（アクシオス） / Fetch API
フロントエンド（画面）から、サーバーや外部のAPIに通信（データの取得や送信）をするための道具（HTTPクライアント）
・Fetch API（フェッチ・エーピーアイ）
ブラウザ標準の機能：JavaScriptに最初から備わっている機能だから、何か特別なインストールをしなくてもそのまま使える。
特徴：少しコードが長くなりがち（例えば、受け取ったデータを .json() に変換するひと手前が必要だったりする）。

・Axios（アクシオス）
外部の便利ライブラリ：使うためにはインストールが必要だけど、みんなよく使っている定番のツール。
特徴：最初からデータをJSONとして自動でパース（変換）してくれたり、エラーハンドリング（失敗したときの処理）が書きやすかったりと、「Fetchより便利でスマートに書ける機能」がたくさんついている。

7.GraphQL
欲しいデータだけを、1回の通信でピンポイントにお願いして取ってくる仕組み
従来のやり方（REST API）の場合
/api/user/1 というURLにアクセスすると、「名前、メールアドレス、住所、注文履歴、お気に入りリスト…」など、サーバー側であらかじめ決められたすべてのデータがセットで返ってきてしまう。
もし「名前だけ」が欲しいときでも、余計なデータまで大量についてきて通信が無駄になったり、逆に「名前と注文履歴を同時にほしい」というときに何回も通信（APIを複数叩く）しないといけなかったりする。

GraphQL の場合
フロントエンド側からサーバーに対して、「今はこのデータとこのデータだけがほしい！」と書いた手紙（クエリ）をそのまま送る。
サーバーはその注文通りのデータだけをピタッと組み立てて返してくれる。

メリット:
画面ごとに「必要なデータだけ」を取ってこれるので、スマホアプリや複雑なReactアプリですごく効率が良い。
エンドポイント（URL）が基本1つしかないので、APIの数が爆発して管理が大変になることがない。

デメリット:
サーバー側の設定や仕組み（スキーマ定義など）が、普通のREST APIに比べて少し難しくて大げさになりがち。

8.React Native
Reactの知識（書き方や考え方）をそのまま使って、スマホアプリ（iOS / Android）が作れるフレームワーク

9.Docker
Docker（ドッカー）は、アプリを動かすための「環境（OSやライブラリ、設定など）ごと箱詰めして、どこでも同じように動かせるようにする仕組み（コンテナ技術）」

10.Sequelize
Node.jsでRDB（リレーショナルデータベース：PostgreSQLやMySQLなど）を操作するための超定番の「ORM（オーアールエム）」というライブラリ

11.Render
